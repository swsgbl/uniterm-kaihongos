- **模式C(产品核心,原生实现)**:把 hmharness 的智能体内核设计(while 循环内核/OpenAI 兼容/流式思考块/上下文预算压缩/审批门/会话审计)在应用内以 ArkTS 原生重实现——工具面=终端写入/读屏/SFTP/连接控制(bigmodel function-calling)。**自包含、商店审核友好(无外部服务依赖)、且是自有框架的自有实现=软著独创性主力**。
- **模式B(增强模式,可选)**:应用内配置"harness 服务地址",连接宿主侧运行的 hmharness Web 流式 API(其 Web 前端已支持浏览器流式/远程审批/会话回放)——多智能体/自进化/800+ MCP 生态全量能力,适合自用高阶场景。**前提:hmharness package.json 的 license 字段当前为空,发布集成文档前需定许可证**。
- **不做**:Node 上机编译(hmharness 需 Node≥22,KaihongOS 无官方 Node,移植成本不成比例)。
- 实施序:M6-2 品牌布局改版 → M6-3 AI 智能体(模式C 先行,B 作为设置项)。

## 一、差异化整改矩阵(合法合规 + 利于软著/商店一次过审)

### 核心法律原则(先立底线)
1. Apache-2.0 允许衍生与商用——我们**本就合法**;"规避"指**原创表达**(视觉/交互/命名),不是隐藏来源;
2. **合规声明必须保留且不可删**(LICENSE/上游版权声明/修改声明)——删了反而违法;正确姿势=自有品牌+清晰的开源声明页;
3. 著作权保护"表达"不保护"功能思想"——功能可以一样,**表达(布局/配色/图标/文案)必须自有**;
4. 我们的技术实现已天然高度差异(ArkTS 重写/自研协议栈/native 模块)——这是软著独创性的主体。

### A. 品牌层(必改,当前违规风险点)
- [ ] 应用名:uniTerm → **一站AI终端 / One AI Term**
- [ ] 包名:net.uniterm.poc → **com.oneaiterm.terminal**(三处同步:AppScope/module/signing)
- [ ] **图标:弃用官方 appicon,原创图标**(当前用的是 upstream/build/appicon.png——必须换)
- [ ] 关于页:自有版权声明 + "基于开源项目 uniterm(Apache-2.0)二次开发"声明 + 原协议文本入口
- [ ] 代码命名空间去 uniterm 化(UniTheme→AppTheme、uniterm.* hilog tag→oneaiterm.* 等)

### B. GUI 布局层(与官方显著错开;官方=38px 顶栏 TabsList+280px 左侧栏+StartTab+#14171d/#22d3ee)
选型(推荐①,用户可改):
1. **命令栏+可折叠导航坞+底部状态栏**:顶栏改为搜索框居中的"命令栏"(Ctrl+K 命令面板);左侧改为**可折叠导航坞**(图标窄条/展开双态,非官方常宽侧栏);底加状态栏(连接状态/传输速率/编码);StartTab→"工作台首页"(卡片流布局自设)
2. 三栏工作台(会话列+主区+右侧信息坞)
3. 顶部 Tab+右侧功能坞
- [ ] 配色弃官方 token(#14171d/#22d3ee/#15191f/#0078d4)→ 自有 palette(建议:深空墨蓝底 #0F1220 + 琥珀强调 #F5A524 / 浅色暖白 #FAFAF7;token 命名自有)
- [ ] 图标集整体更换(开源图标库:Tabler/Lucide 风格,区别于官方)
- [ ] 密度/圆角/阴影/动效自有风格(如 8px 圆角+柔和阴影,官方是锐利小圆角)

### C. 交互与功能表达层
- [ ] 连接管理:树形→**列表+分组标签**(或保留树但行样式/交互重设计)
- [ ] 设置:菜单式→**导航式设置中心**(左分类+右表单)
- [ ] AI:侧栏→**可折叠底部 Dock 或右侧抽屉**(位置与官方错开)
- [ ] 新增自有特色功能(加独创权重):命令面板、快捷脚本库、会话录制回放、连接测速、主题自定义
- [ ] 全部文案/术语自有("工作台/连接器/凭据库",不用官方词汇)

### D. 软著与提审材料策略
